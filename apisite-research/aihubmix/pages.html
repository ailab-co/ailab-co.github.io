页面逐一解析

按区域分组，共 31 个页面 / 功能块、63 张截图。每张图下方的「原网页」可以直接打开；控制台页面标注「需登录」，少数弹层地址标「路由推断」。点图放大后可用 ← → 切换，按 Esc 关闭。

登录与注册

登录 / 注册弹窗

布局与组件
未登录访问控制台任何页面，背景虚化并居中显示登录卡；提供 GitHub、Google、邮箱三种方式。注册卡要求勾选条款，下方单独一行企业入口。
UX 观察
优点：登录后回到原来要访问的页面（推断，依据：卡片盖在目标页上）。企业入口在注册环节就出现。问题：我方域名邮箱被直接拒绝，没有说明原因，也没有其他途径。
对我们
登录卡上方保留目标页的轮廓，能减少用户「我在哪」的困惑；被拒时应该说明原因（例如域名黑名单）并给出联系方式。

控制台 · 账户级

控制台首页

布局与组件
标题「AIHubMix Dashboard」加副标题，左栏是 ACCOUNT 级 10 项菜单。
UX 观察
截图时处于加载态，只有标题。（真实首页内容本次未见完整版。）
对我们
首页应该直接给余额、本月花费、快速创建 Key、第一段请求代码。

Workspaces 工作区

布局与组件
表格列：Name / Description / Spend / Keys / Actions；右上角显示配额「1 of 5」；新建弹窗填 Name、Slug（创建后不可改）、Description。
UX 观察
默认工作区带 Default 标；面包屑可以直接切换或新建工作区。
对我们
把「令牌分组」包装成「项目 / 工作区」，每个项目单独显示花费和 Key 数。

Profile 个人概览

布局与组件
三张 KPI 卡（本月花费、请求数、总 tokens）+ GitHub 风格的年度调用热力图 + API Key 概况表。
UX 观察
热力图有趣味，也让人产生「连续使用」的感觉；概况表让用户一眼看到各 Key 的花费。
对我们
可放在 P2：先做 KPI 卡和 Key 概况，再考虑热力图。

Activity 用量分析

布局与组件
一行 KPI（总花费、请求数、Token 量、缓存命中率、混合单价 $/1M）+ 7 张图（Top API Keys、Top apps、按模型用量、用量类型、按模型请求量、Token 构成、Prompt 缓存）；筛选维度 Model / Provider / App / API key；时间范围从 Today 到 Past year，支持自定义；右上角可选时区（截图为 GMT-5）。
UX 观察
缓存命中率和混合单价两项指标很少见，能直接回答「我花得值不值」。时区可选，避免按 UTC 统计造成误解。
对我们
中转站用户最常问「钱花哪了」：P1 做按 Key / 模型的花费图和缓存命中率；时区默认设成 Asia/Shanghai。

API Key 列表与创建

布局与组件
列表列：Name/key、Workspace、Belongs to、本月花费、Limit、Expires、Last used，支持状态筛选、搜索、导出。创建用右侧抽屉：Workspace、Name、Credit limit、Structured Output Repair、Expires、模型范围、IP 限制、模型名映射（0/5）、失败回退（0/3）。
UX 观察
字段多，但抽屉分段清楚，BETA 功能有标注和数量上限（0/5、0/3）。Last used 帮助清理不用的 Key。
对我们
P0：额度、过期、模型白名单、IP 白名单；P1：模型映射、失败回退（new-api 渠道层已有类似能力，可以下放到 Key）。

Request logs 请求日志

布局与组件
列：Date / Model / Provider / App / Input / Output / Cost / Finish reason；筛选器可搜索（Model / App）；Table settings 支持拖拽排序列、钉住列、调整密度。（API Key 列表页有 Export CSV；日志页本次未见导出按钮。）
UX 观察
空态文案会建议「试试更长的时间范围」。Finish reason 一列帮助排查截断问题。
对我们
日志加 Finish reason 和 trace id，并支持列设置，对排障很有用。

Credits 余额与充值

布局与组件
详见概览页「计费、余额与价格展示」。右侧是 Auto Top Up 卡片；顶栏语言菜单列出十余种语言（中、日、德、西、法、葡、俄、波、荷、意、越、乌等）。
UX 观察
手续费由平台承担，并在弹窗里明说；底部显示当前账户，防止充错号；发票要走工单，比较麻烦。
对我们
P0：预设金额 + 支付方式 + 兑换码 + 交易记录；把发票入口做成自助表单。

⌘K 全局搜索

布局与组件
弹层搜索页面、API Key、模型三类对象，默认显示最新模型，底部有键盘操作提示。
UX 观察
高级用户可以不碰菜单直接跳转。
对我们
P1：先做「搜模型 + 搜页面」。

Inbox 站内信

布局与组件
铃铛打开右侧抽屉，四个页签：All / System / Models / Changelog；模型消息卡片带海报、价格和「View model」。
UX 观察
把上新、调价、下线这类消息集中起来，减少用户去群里追公告。
对我们
P1：站内信 + 公告页签；新模型消息直接链接到模型详情页。

Developer：MCP / CLI / HTTP

布局与组件
三个页签共用一把 Management Key。MCP 页签选客户端，看 12 个工具（凭证类型 / 是否计费）；CLI 页签分三步安装，11 条命令；HTTP 页签列 9 个端点，带 Read / Write / Destructive 标签。
UX 观察
每个工具都写清凭证和计费，信息透明；但 GET 接口会轮换 Key，属于设计上的坑。
对我们
P2：先做只读的管理 API（余额、用量、Key 列表），所有写操作用 POST。

Notifications 通知

布局与组件
分组：Budget & Spend / Models / Account & Services / Delivery destinations。规则包括低余额、新模型、模型下线、模型调价、产品更新、促销、安全告警。低余额抽屉里填阈值（默认 $1）和推送方式（Inbox / Email 必选，Webhook 可选）。
UX 观察
每条规则是一个开关加一个配置抽屉，结构清晰；Webhook 作为独立的「目的地」统一管理。
对我们
P0：低余额邮件告警；P1：下线 / 调价通知 + Webhook（企业微信 / 飞书 / 钉钉）。

Support 支持

布局与组件
先列常见问题卡片（401 / 403 / 429、连不上、有余额仍失败）→ Browse all FAQs；New ticket 抽屉：回复邮箱、分类、标题、描述（0/10000）、附件、Trace ID。
UX 观察
先让用户自助排查，再开工单；Trace ID 让客服能直接定位请求。
对我们
P0：错误码 FAQ；P1：工单带 trace id（中转站常见的「群里截图问客服」可以由此减少）。

Preferences 偏好设置

布局与组件
Personal account（Manage account）、Balance reminder、Invite link + Copy、Personal account deletion（红色危险区，15 个工作日审核）。左上角头像下拉是账户级菜单全集 + Sign out。
UX 观察
危险操作单独放在红色区域；邀请入口放得比较深。
对我们
如果邀请是我们的主要增长手段，入口应该放到首页或顶栏。

控制台 · 工作区级

工作区 Overview

布局与组件
面包屑两级（Personal / Default workspace）；左栏换成 WORKSPACE 级 7 项；Usage summary 可以切换 Tokens / Spend / Requests。
UX 观察
用户能明确感知「现在在哪一层」；「← Account」随时返回账户级。
对我们
做项目层时，用面包屑而不是另起一套导航。

官网 · 模型与价格

官网首页

布局与组件
Hero「The Unified Gateway for AI Models」+ 三个要点（730+ models / Official cloud routes / Pay as you go）→ 三张卖点卡（一个 Key、SDK 直接替换、跨云容灾）→ 桌面客户端 → 生态 → Model Rankings → Blog → 四列页脚。
UX 观察
首屏用一句话讲清楚定位，往下是证据（渠道、排行、生态）；但首页的 730+ 和模型广场的 954 对不上。
对我们
首页三件事：一句话定位、价格入口、「3 步接入」代码。

Models 模型广场

布局与组件
左侧筛选（输出模态 / 类别 / 厂商 / Refine）+ 右侧卡片网格；顶部显示模型数和 Models API 入口。
UX 观察
价格、上下文、速度在列表页就能比较；折扣胶囊很醒目。筛选区偏高，首屏能看到的卡片少。
对我们
P0：价格页卡片显示「输入 / 输出价 + 上下文 + 折扣划线」，筛选区默认收起。

模型详情

布局与组件
左侧锚点导航，右侧依次是 Pricing → Specifications → Providers → Performance → Usage → Try this model → FAQ → Compare → More models。能力清单里不支持的项灰显。
UX 观察
把「这个模型多少钱、走哪个渠道、稳不稳、怎么调」放在一页里讲清楚。
对我们
P1：每个模型一页详情：价格、上下文、能力、示例代码；P2：渠道 Uptime。

Compare 对比

布局与组件
最多 4 个模型并排，选择写进 URL，下方列出 Popular comparisons。
UX 观察
可分享的 URL 带来 SEO 和社群传播（推断）。
对我们
P2。

LLM Router

布局与组件
左边是策略说明，右边是代码窗口；下方评分表按任务分类给每个候选模型打分，并显示价格和 TTFT。
UX 观察
公开的评分表让「auto」不再是黑盒。
对我们
P2：如果要做「智能路由」，先公开路由规则。

Model Retirements 模型下线

布局与组件
顶部统计 12 个计划下线、120 个已下线；说明三种状态；按厂商筛选；表格列出公告日、下线日、替代模型。
UX 观察
这是同类站里少见的页面，直接回答「我用的模型还能用多久」。
对我们
P1：中转站模型变动频繁，一个公告日历加替代建议就能明显减少客服压力。

官网 · Playground

Playground

布局与组件
左栏 12 类能力（Text / Image / Speech / Video / Transcription / Realtime / Embeddings / Rerank / OCR / Moderation / Search / Decision），中间是模型卡（价格、上下文、Provider），右边是参数面板。图像参数：6 种比例、宽高、png / jpeg / webp / gif / svg；视频参数：7 种比例、480P / 768P、5 秒。
UX 观察
未登录先弹登录，余额为 0 时弹充值，「试用 → 付费」的转化路径很短。历史只保存在本机，页面上有说明。
对我们
P1：网页版 Playground（先做文本 + 图像），余额不足时直接引导充值。

官网 · 生态与企业

Ecosystem / Apps

布局与组件
首屏三个社会证明数字 + Featured 卡片；下面依次是分类浏览、社区应用、开发者计划表单、App Code 说明和 FAQ。
UX 观察
卡片标注集成方式（Built-in / Compatible / Plugin / Package），用户可以判断接入难度。
对我们
P1：「在 Cherry Studio / Cursor / Claude Code 里怎么用」的教程卡片，对中转站用户最实用。

Enterprise 企业站

布局与组件
独立子域、衬线大标题、四个大数字、三种协议代码切换；Contact Sales 表单收集月花费区间和合规需求。
UX 观察
把企业销售和自助控制台分开，各自讲各自的话。
对我们
P2：先做一个「企业 / 团队采购」表单页即可。

About 与页脚

布局与组件
主体信息、联系邮箱、四列页脚。
UX 观察

Blog

布局与组件

UX 观察
内容同时起到教育用户和 SEO 的作用（推断）。

Status 状态页

对我们
