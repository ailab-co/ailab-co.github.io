P0P1P2避免

对我们中转站用户端的借鉴

按优先级排列。P0 是重做用户端时必须有的；P1 能明显拉开和模板站的差距；P2 等有需求、有数据之后再做。每一条都注明了参考的是 AIHubMix 的哪个页面。

一句话：先学 AIHubMix 的「价格透明 + Key 策略 + 日志可追溯 + 余额告警」，这四件事做完，中转站最常见的「扣费说不清、模型突然不能用、余额用完才发现」三类投诉都能少一大半（推断）。工作区、路由、MCP 这些企业级能力暂时不急。

P0 必须有

  1. 控制台首页 = 余额 + 本月花费 + 「创建 Key → 复制代码」

    对应 AIHubMix 的 Profile KPI 卡和 Quick Start。新用户 1 分钟内能完成第一次请求。首页不要只放一个标题或营销图。

  2. Key 创建抽屉：额度 / 过期 / 模型白名单 / IP 白名单

    对应 AIHubMix 的 Key 抽屉。new-api 后端大多已有这些字段，主要工作是重做表单分组、加上说明文字，并在列表里显示 Last used 和本月花费。

  3. 请求日志：时间 / 模型 / 输入 / 输出 / 费用 / 状态 + 筛选 + 导出

    对应 Request logs。加上 trace id 和 Finish reason，并支持按 Key / 模型筛选、导出 CSV，可以减少大量「这笔扣费怎么来的」类咨询。

  4. 价格页：卡片直接显示单价、上下文、折扣划线价

    对应 /models 卡片。筛选区默认收起，让首屏多显示几个模型；图像和视频用矩阵或按秒的价格表。

  5. 充值弹窗：预设金额、支付方式、手续费说明、兑换码、交易记录

    对应 Purchase Credits。写清楚手续费由谁承担、最低充值金额，弹窗底部显示当前账户。

  6. 低余额告警（邮件 / 站内信）

    对应 Notifications 的低余额规则。提供默认阈值，用户首次充值后自动开启。

  7. 错误码 FAQ + 主体 / 条款 / 退款说明

    对应 Support 的常见问题卡片和 Legal 页。401 / 403 / 429 / 余额不足这几类错误写成一页，并在报错信息里附上链接。

P1 拉开差距

  1. 项目（工作区）层

    把令牌分组包装成「项目」，每个项目显示自己的花费、Key 和日志；用面包屑切换，不另起一套导航。

  2. 用量分析图表

    按 Key / 模型 / 日期显示花费，展示缓存命中率；时区默认 Asia/Shanghai。

  3. 模型公告：上新 / 调价 / 下线日历 + 替代建议

    参考 Retirements 页和 Inbox 的 Models 页签；下线模型返回明确的错误码。

  4. 公开状态页

    按协议或模型族拆分组件（OpenAI 兼容、Claude 兼容、Gemini 兼容、图像），可以订阅。

  5. 站内信 + ⌘K 搜索模型

    让新模型消息能一键跳到模型详情和 Playground。

  6. 网页 Playground，余额不足时引导充值

    先做文本和图像两类。

  7. Webhook 通知（飞书 / 钉钉 / 企业微信）

    把低余额、下线、调价等事件推送到群里。

  8. llms.txt / agents.md + 模型详情页

    成本低，对 AI 编程工具用户有用。

  9. 「在 XX 工具里使用」的教程卡片

    Cherry Studio、Cursor、Claude Code、Dify 等，参考 Ecosystem 页。

P2 以后再做

  1. Key 级模型映射和失败回退

    把渠道层已有的能力开放给用户，配合「BETA + 数量上限」的方式试运行。

  2. model="auto" 路由，并公开评分规则

    先公开规则，再上线功能。

  3. 管理 API / CLI / MCP

    先做只读接口，写操作一律用 POST，并在页面上标注凭证和计费。

  4. Compare 对比页、模型渠道 Uptime

    需要先积累监控数据。

  5. 企业 / 团队：成员、组织余额、审计、销售表单

    需求明确后再做。

  6. Profile 热力图、自动充值、多语言

    有了更好，不是必需。

避免 不要学的地方

  1. 同一个指标在不同页面给出不同数字

    AIHubMix 的模型数有 730+ / 954 / 961 / 500+ 四种说法。我们的模型数、可用率、价格应该只从一个数据源生成。

  2. 筛选区占满首屏

    价格页的筛选区默认收起，或做成一行横向标签。

  3. 拒绝注册却不说明原因

    被风控拦截时，应该说明原因并给出申诉或联系方式。

  4. GET 请求带副作用

    查询接口不能轮换 Key 或修改数据。

  5. 发票、退款只能走工单

    至少提供自助申请表单，并显示处理进度。

  6. 营销图里放看起来像真实账户的数字

    首页示意图里的余额（如 $128.40）容易被误认为是用户的真实数据，示意图应该明确标注为示例。

  7. 字体过多

    AIHubMix 在不同页面用了三四套字体。我们统一用一套无衬线字体加一套等宽字体即可。

  8. 照搬企业级复杂度

    组织、成员、审计、路由策略等功能，个人用户为主的中转站暂时用不上，先把 P0 做扎实。
