P0P1P2短板

对我们中转站用户端的借鉴

按优先级排列。P0 是重做用户端时必须有的；P1 能明显拉开和模板站的差距；P2 等有需求再做。每一条都注明了参考的是 kie.ai 的哪个页面。最后一节是 kie.ai 的短板，不要学。

一句话：kie.ai 最值得学的是「Key 弹窗的安全默认值」和「官方价对比式的价格页」，其次是把限流、保留期、失败不扣费这些规则写在用户会看的页面上。它的短板集中在可信度（没有状态页、数字前后不一、支持入口不全）和接口约定（错误返回 200、签名不覆盖请求体）。和 AIHubMix 合起来看：价格页、Key 弹窗学 kie.ai，日志、通知、状态页、工单学 AIHubMix（见 对比表）。

P0 必须有

  1. Key 创建弹窗：有效期 + IP 白名单（默认推荐）+ 模型范围 + 花费上限

    参考 kie.ai 的 Create API Key。提供「最近调用过的 IP」「检测我的服务器」两种快捷方式；列表用黄色图标标出「任意 IP / 永不过期 / 未设上限」的 Key。new-api 系后端大多已有这些字段，主要是重做表单。

  2. 价格页加「官方价 + 折扣 %」，多媒体按分辨率 / 时长逐行列

    参考 /pricing 和首页对比表。积分和人民币 / 美元并列；对比依据（官方或第三方）写在表头；页签计数按模型算，不要按价格行算。

  3. 把规则写在用户会看的地方

    限流写在充值页，保留期写在日志页顶部，「失败不扣费」写在首页和价格页。参考 kie.ai 的 Rate Limit 卡和 Logs 横幅。

  4. 日志支持按任务 ID 搜索 + 状态筛选 + 每条扣费

    参考 /logs。中转站做图像 / 视频后，这是核对扣费的唯一依据，kie.ai 文档也这么写。

  5. 「接入必读」一页

    参考 docs 的 Getting Started（Important）：Base URL、请求头、限流、失败计费、保留期、支持时段、稳定性预期，全部一页说清。

  6. 充值套餐带赠送比例角标

    参考 $500 SAVE 5% / $1250 SAVE 10%。角标里的比例要和实际赠送一致（kie.ai 换算后是对得上的）。

  7. 视频模型写出计费公式

    参考 Seedance 2.5 页：按秒、按分辨率、输入时长是否计费。减少「为什么扣这么多」的争议。

P1 拉开差距

  1. 模型详情页：价格表 + Playground + 代码示例

    参考 kie.ai 模型页的页签结构；价格用表格，不要用长句。

  2. 模型列表按「厂商 + 用途」筛选，筛选写进 URL

    参考 /market/lip-sync。卡片上直接显示起价。

  3. 回调重发（单条 / 批量）

    参考 Logs 的 Retry Callback / Batch Callback。

  4. 上新 / 调价公告流，每条带「去试用」

    参考 /api-updates 与 /changelog 共用一份数据。

  5. 付费客户专属群（飞书 / 企业微信）+ 低余额提醒

    参考 VIP 私密频道；比 Discord 更适合国内客户。

  6. 推广返佣：申请制 + 安全期 + 防刷 + 周结算

    参考 Affiliate 规则；演示数据要明显区分。

  7. 开放查余额接口 + 回调签名

    参考 GET /api/v1/chat/credit；签名覆盖时间戳和请求体。

  8. 自动充值

    参考 Billing 的 Auto top-ups，最多 10 分钟扣一次的节流规则可以照搬。

P2 以后再做

  1. 轻量团队邀请

    参考 Settings 的邮箱邀请 + 角色显示。

  2. AI 编程工具配置教程 / skill

    参考 docs 的 AI Agents 和 npx skills。

  3. Blog 文章页侧栏放模型卡和试用按钮

    参考 Blog 文章页的 API Directory。

  4. 多语言、深色模式

    有需求再做。

短板 kie.ai 的弱点，不要学

  1. 错误也返回 HTTP 200

    kie.ai 的 /api/v1/* 错误用 200 + 响应体 code。OpenAI 兼容客户端和网关一般按状态码重试、熔断，我们应保持标准状态码。

  2. 回调签名不覆盖请求体

    只签 taskId 和时间戳，请求体被篡改也校验得过（推断）。我们的签名应覆盖时间戳 + 原始请求体。

  3. 同一指标多个数字

    模型数 124 / 138 / 200+ / 654 行，开发者 120,000+ / 1,000+。数字应来自同一数据源。

  4. 看起来能点的「实时状态」不能点

    要么接真实状态页，要么不放状态指示。

  5. 支持入口挂着却没有目标

    Telegram 支持在侧栏、FAQ、About 里都出现，但没有可点击目标；VIP 页只有 Discord。

  6. 价格说明写成一整段

    GPT Image 2.6 页把多个子模型、多种 token 价格挤在一段里。

  7. 隐私政策与实际不符

    写「只收集邮箱、不用 cookies」，实际有手机号登录和 Google Analytics。

  8. 只能用海外账号或手机号登录

    kie.ai 不支持邮箱注册（只有 Google、Microsoft、手机号）。国内中转站至少保留邮箱或手机号 + 微信。

  9. 中文路由下放英文内容

    /zh-CN/blog 是英文。要么翻译，要么不放中文入口。
