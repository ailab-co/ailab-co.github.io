页面逐一解析

按区域分组，共 26 个页面 / 功能块、43 张截图。每张图下方的「原网页」可以直接打开；控制台页面标「需登录」，其余标「公开」。点图放大后可用 ← → 切换，按 Esc 关闭。

控制台

Models Market 模型市场

布局与组件
控制台外壳。顶部轮播推新模型；「All Models」后跟数量；搜索框带 ⌘K；27 个厂商标签（彩色圆点）+ 15 个任务标签；下方 5 列深色封面卡，卡片左上厂商角标、底部任务标签，分页。
UX 观察
点任务标签后地址变成 /market/lip-sync，显示「7 models found」，筛选结果能直接分享，也利于 SEO。未登录可访问。厂商和任务两组标签共占约 4 行，首屏可见卡片不多。
对我们
P1：模型列表按「厂商 + 用途」两组标签筛选，筛选状态写进 URL；卡片上直接显示起价（kie.ai 市场卡片没显示价格，首页精选卡片有）。

Pricing 价格表

布局与组件
页签按模态分 All / Chat / Video / Image / Music，带计数，右侧搜索。每个模型一个分组卡，组内逐行列出「模式 × 分辨率」，四列：Credits / Gen、Our Price（蓝色）、Official / Fal Price、DISCOUNT（绿色）。
UX 观察
用户能一眼看到「比官方便宜多少」，对比依据（官方或 Fal）写在表头。按价格行计数（654）而不是按模型计数，和 Market 的 124 对不上。
对我们
P0：价格页加「官方价 + 折扣」列；多媒体模型按分辨率或时长逐行列价；页签计数统一按模型算。

API Keys 列表与创建

布局与组件
列表列：Name（含创建时间和创建人）、Key（掩码）、Expires、IP Whitelist、Allowed Models、Safe-Spend Limits、⋮ 菜单。创建弹窗：Name → Expiration（1/7/30/90 天/Never，选 1 天给出失效时间提示）→ IP Access（默认推荐「只允许指定 IP」，最多 10 个 IPv4/IPv6 或 CIDR）→ Model Access（All / Specific）；未填名称时 Create 置灰，底部提示「Please enter a name」。
UX 观察
安全默认值做得好：任意 IP 时列表用黄色警示图标，顶部蓝条提醒「1 key 可从任意 IP 调用」。「检测我的服务器」「最近调用过的 IP」降低了填写 IP 的门槛。弹窗明说密钥只显示一次。
对我们
P0：照这个弹窗做；默认推荐 IP 白名单，并提供「最近调用 IP」一键加入；列表用警示图标标出「任意 IP」「永不过期」「未设花费上限」的 Key。

Billing 余额与充值

布局与组件
左卡：余额 + 刷新时间 + 「永不过期」+ Rate Limit 说明（每账户每 10 秒 20 个、超出 429 不排队、如需提额联系客服）。右卡：4 档套餐（$500 / $1250 带 SAVE 角标）、支付方式页签、账单地址、Buy Credits。下方自动充值开关、交易记录 / 账单资料页签。
UX 观察
把限流写在付钱的页面上，减少「为什么 429」的咨询。套餐角标直观。卡支付要账单国家和邮编，中国用户可能不熟悉。
对我们
P0：充值页预设金额 + 赠送比例角标；把并发 / 限流规则写在充值页。P1：自动充值。

API Usage 用量

布局与组件
日期范围选择 + Export；Total Spend 图可切 Spend / Credits；下方按 API 接口、按 API Key 两个表。
UX 观察
空账户只看到空态，看不出有数据时图表的细节。
对我们
P1：用量页按 Key、按模型两个维度，并允许导出。

Logs 任务日志

布局与组件
顶部保留期横幅；筛选：模型、Task ID、状态（running / success / failure）、日期；按钮 Batch Callback、Refresh；列：Model & Details、参数、状态、积分、Task ID、Results、Retry Callback。
UX 观察
对异步任务很实用：按 Task ID 查单个任务，回调失败可以单个或批量重发。保留期写在页面顶部，用户不会事后才发现文件被删。
对我们
P0：日志支持按任务 ID 搜索、按状态筛选，显示每条扣费；P1：回调重发；保留期写在页面顶部。

Affiliate Program 推广返佣

布局与组件
顶部结算币种提示（加密货币订单暂不计佣）；页签 Dashboard / Invites / Orders / Withdrawals / FAQ；蓝色招募横幅 + Apply Now；4 张统计卡（总收益、待结算、可提现、已提现）；推广链接框显示「Pending approval」。
UX 观察
未申请时用 DEMO 数据展示仪表盘长什么样，每张卡都有 DEMO 标签。规则写得具体（15%、前 30 天、45 天安全期、每周结算）。但演示金额（$1,450）可能被误认为真实收益。
对我们
P1：做推广计划时，规则写清楚，加安全期和防刷；演示数据要用更明显的方式（如整块置灰）。

API Updates 更新流

布局与组件
控制台内的更新流：搜索 + 「All APIs」筛选；每条卡片有日期、标签、标题、文档链接、Key Features、试用链接。
UX 观察
和公开的 /changelog 内容相同，一份数据两处展示；每条都能直接跳去试用。
对我们
P1：模型上新 / 调价公告页，每条带「去试用」「看文档」两个按钮。

Settings 团队与设置

布局与组件
一页长卡片：Team & Settings（邮箱邀请成员、成员列表）、Webhook HMAC Key、Theme（Dark Mode）、Time Zone、Notification（Email Subscription）、Danger Zone（删除账户）。侧栏底部语言浮层 12 种。
UX 观察
所有设置平铺在一页，不用找。团队功能很轻：只有邀请和角色显示。
对我们
P2：轻量团队邀请；时区设置默认取浏览器时区。

模型页

模型页 Playground（图像）

布局与组件
公开顶栏布局。面包屑 Market / 厂商 / 模型；标题「厂商 / 模型名」+ 复制按钮；Commercial use 徽章；「Part of the OpenAI API family」链接；右上 Run with API、Copy page；Model Type 按钮组（6 个变体）；价格说明；页签；左 Input（Form / JSON）右 Output（Preview / JSON）。
UX 观察
一页内能完成「看价格 → 试跑 → 拿代码」。但价格说明是一整段长文本，多种 token 价格挤在一起。
对我们
P1：每个模型一页，含价格、试用、代码；价格写成表格，不要写成长句。

API 页签

布局与组件
内嵌 Apidog 风格的接口文档：端点、参数、Try it、Shell / JS / Java 示例，Example 1/2/3。顶部横幅引导 AI Agents 指南。
UX 观察
开发者不用跳去文档站。
对我们
P1：模型页直接给 curl / Python 示例，Base URL 和模型名自动填好。

视频模型：Seedance 2.5

布局与组件
按分辨率 × 是否带视频输入列每秒价格，并解释计费公式；Model Type 有 Seedance 2.5 和 Draft；表单含首尾帧、提示词、参考图 / 视频 / 音频、generate_audio、分辨率、比例、时长、输出格式、web_search、draft。README 页签是一篇发布说明长文。
UX 观察
把计费公式写出来，避免「为什么带视频输入反而更贵」的争议。价格注明「beta，可能调整」。
对我们
P0：视频模型价格写清计费公式（按秒、按分辨率、输入时长是否计费）。

对话模型：GPT-6.1 Sol

布局与组件
每 1M tokens 四档价格（输入、缓存读、缓存写、输出）+「比官方低 70%」；对话 Playground：Memory、Function calling、Web Access、Reasoning effort（Low–Max）、Stream。
UX 观察
缓存读写单独标价，对长上下文用户很重要。
对我们
P0：对话模型价格至少列输入 / 输出 / 缓存三项。

音乐模型：Suno API

布局与组件
20 个功能按钮（生成、续写、翻唱、混搭、加人声、分离人声、MIDI、WAV 等），每个功能单独计价和单独的表单，输出区有 Overview / JSON。
UX 观察
一个模型页承载 20 个子功能，按钮很多但分得清。
对我们
P2：多功能模型用按钮组切换，价格随功能变化。

公开站

首页首屏

布局与组件
Hero 一句话定位 + 两个 CTA（探索 AI API / API 文档）+ 社会证明（120,000+ 开发者 · 80+ 国家/地区）+ 模型缩略图切换 + 指标卡（99.9% 正常运行时间、24/7 支持、$0 月费、平台实时状态、获取支持）。
UX 观察
定位清楚，三条承诺放在首屏。「平台实时状态」看起来像链接但不能点。
对我们
首页首屏：一句话定位 + 价格入口 + 三条承诺；状态指示要么接真实状态页，要么不放。

首页：价格对比与精选模型

布局与组件
对比表四个页签，每行 KIE 价 / 折扣 / 划线官方价，用等宽字体；精选模型两行自动滚动卡片，带类型标签、起价、ONLINE、试用按钮。
UX 观察
「省多少」用大号绿色百分比，非常直观。自动滚动的卡片不方便细看。
对我们
P0：首页放 6～10 个热门模型的「我们价 vs 官方价」。

首页：FAQ、CTA 与页脚

布局与组件
左侧「还有疑问?」卡片列 Discord / Telegram / API Docs；右侧 16 条带分类标签的手风琴 FAQ（失败不扣费、积分不过期、发票、限流、保留期、VIP 支持等）。底部 CTA「获取免费 API Key」，页脚三组链接。
UX 观察
FAQ 覆盖了计费和限流的核心问题。
对我们
P0：FAQ 至少覆盖扣费规则、失败是否计费、限流、发票、退款。

Changelog 公开更新

布局与组件
Hero「1,000+ Developers, 99.9% Uptime, Enterprise-ready」+ 搜索 + 更新卡片流。
UX 观察
和首页的 120,000+ 矛盾，说明营销数字没有统一来源。
对我们
数字统一从一个配置生成。

VIP 支持

布局与组件
标题「加入您的私密 VIP 支持频道」；四个卖点：优先协助、实时告警、低余额提醒、私密频道；只有一个 Discord 按钮。
UX 观察
私密频道对付费客户有吸引力，但只支持 Discord，和其他页面写的「Discord 或 Telegram」不一致。
对我们
P1：给付费客户开专属飞书 / 企业微信群，配低余额提醒。

Blog

布局与组件
列表三列卡片（标签、封面、标题、摘要、作者、日期）；文章页 TLDR + 右侧吸附模型目录卡 + Get API Key。
UX 观察
文章页就是转化页。/zh-CN/blog 下是英文内容。
对我们
P2：如果做内容，文章页侧栏放「相关模型 + 立即试用」。

About / Contact

布局与组件
About：我们是谁、提供什么、公司信息（NEXUSAI SERVICES LLC、Denver 地址、邮箱）。Contact：支持与计费邮箱、VIP 频道、开发者资源、邮寄地址。
UX 观察
主体和地址公开，加分。
对我们
P0：写明运营主体和联系方式。

法务页

布局与组件
退款政策（可退，邮件附订单号）、服务条款（生效 2025-08-01，更新 2026-10-26）、隐私政策（生效 2025-08-01）。
UX 观察
退款写明了流程。隐私政策「只收集邮箱、不用 cookies」与手机号登录、使用 Google Analytics 的事实不符。
对我们
P0：服务条款、隐私、退款三页，内容和实际登录方式、统计工具保持一致。

文档

Getting Started（Important）

布局与组件
一页 11 节，从模型、价格、Key 安全到限流、支持时段、稳定性预期、团队介绍。
UX 观察
把「上线前必须知道的事」集中成一页，标题直接写 Important；限流、保留期、200 不代表完成等坑都提前说。
对我们
P0：做一页「接入必读」：Base URL、Key、限流、失败计费、保留期、支持时段。

任务接口：createTask / recordInfo

布局与组件
每个模型一页 createTask 文档（model + input + callBackUrl），统一用 Get Task Details 查状态；最佳实践写明回调优先、轮询指数退避、视频可能超过 10 分钟、文件 14 天。
UX 观察
所有异步模型共用一套查询接口，接入成本低。
对我们
P1：多媒体模型统一任务接口和状态枚举。

Common API 与 Webhook 签名

布局与组件
Common API：Base URL、查余额、取下载链接。Webhook：HMAC-SHA256 签名 + 时间戳头，Key 在 Settings 生成。
UX 观察
有余额查询接口，方便客户自己做监控。签名不覆盖请求体，安全性弱于常见做法。
对我们
P1：开放查余额接口；回调签名覆盖「时间戳 + 请求体」。

AI Agents

布局与组件
npx skills 一条命令装 kie-models 和 kie-chat-agents；环境变量 KIE_API_KEY；skill 对照表。
UX 观察
把「让编程代理用 KIE 积分」做成卖点。
对我们
P2：给 Claude Code / Codex / Cursor 出一页配置教程，后续再考虑 skill。
