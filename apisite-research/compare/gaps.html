C · 遗漏分析：国内 B2B 中转站容易漏掉的事

事项 为什么重要 三站现状 建议 级别
实名 / 企业认证 国内平台常见做法是先实名再充值、开票；企业认证决定账号归属和能开的发票类型 三站都没有。国内参考：硅基流动要求实名后才能充值和开票，企业可以通过法人人脸识别或对公打款认证 [X5] 个人和企业两种认证；账号归属以认证主体为准 P0
增值税发票 B2B 客户的硬需求；没有发票，企业很难走报销和采购流程 AIHubMix 走工单；kie.ai 手动生成；OpenRouter 在 Stripe 发票上加税号 [OR51]。硅基流动只对已消费金额开票，企业认证可开专票 [X7] 发票中心：按已消费金额申请，专票和普票，查看进度、下载 P0
对公转账充值 企业付款通常走对公账户 三站都没有 先下单再转账，打款账户名须与认证主体一致，到账后自动入账 P0
合同、对账单、预付协议 采购流程需要；也是续费的依据 OpenRouter 企业版有合同和发票付款 [OR2] 月度对账单（PDF / Excel）自动生成；合同模板 P1
合规与备案 面向国内提供生成式 AI 服务、转售境外模型都涉及监管要求（具体义务需律师确认，本报告未核实） 三站都在境外，不适用 上线前咨询律师；写清主体、服务范围和内容安全措施 P0（咨询）
内容安全 国内平台普遍对提示词和输出做安全审核（例如硅基流动的个人信息收集清单把「内容安全与风控」列为收集提示词和输出的用途之一 [X6]） OpenRouter 有护栏，并对 CSAM 做筛查 [OR41] 至少做关键词和接口级审核，并在条款中写明 P0
数据不留存选项 企业客户会问：提示词存不存、存多久、谁能看 OpenRouter 默认不存，私有日志需主动开启 [OR41] 默认只存元数据；内容日志可选，并写明保留期 P1
人民币定价与汇率 上游多以美元计价，汇率波动会影响毛利 三站都是美元 人民币标价；说明调价机制（例如汇率变动超过一定幅度时调整，提前通知） P0
价格变动通知与价格历史 转售客户要向他们的客户报价 OpenRouter 有降价日报 [OR33]；AIHubMix 有调价通知 调价提前 N 天通知；每个模型显示价格历史 P1
渠道真实性（是否掺水、降级） 中转站行业的核心信任问题：用户担心「标的是 A 模型，实际给的是更便宜的模型」 OpenRouter 模型页公开每个渠道，端点数据带量化精度字段，请求时可按量化精度过滤 [OR8] [OR7] [OR13]；AIHubMix 公开渠道 渠道分组写明来源类型（官方 / 云厂商 / 其他）；日志显示实际模型名；定期公开抽检方法 P1
渠道健康度 决定可用率和路由质量 OpenRouter 实时追踪响应时间、错误率和可用性，并据此路由 [OR59] 内部按 5 分钟窗口统计成功率、首字时间和吞吐；对外先公开汇总结果 P0（内部）/ P1（公开）
风控 Key 泄露被盗刷、支付欺诈、批量注册薅羊毛 kie.ai 推广计划用支付指纹防作弊；OpenRouter 对管理接口按 IP 限频 [OR56] Key 异常用量告警和自动冻结；新账号设充值和并发上限；推广设安全期 P0
并发与提额 企业客户要知道上限，以及怎么提额 kie.ai 写明每 10 秒 20 个请求；OpenRouter 付费请求的限流直接沿用上游 [OR1] 限流档位写在充值页；提供自助申请提额 P1
子账号与额度分配 企业内部分部门、分项目用；转售客户要分给他们的客户 OpenRouter 有成员、Key 两级预算 [OR39] 企业账号下设子账号和项目，各自限额；下级额度不能超过上级 P1
代理商 / 分销 / 白标 你做 B2B 转售，下游可能也是转售商 三站都没有 代理商后台：下级账号、加价规则、佣金、对账；P2 再考虑白标域名 P2
审计日志 企业客户要知道谁在什么时候创建、删除了 Key，改了额度 AIHubMix 代码里有审计路由；OpenRouter 有 Key 审计指南（本次未读正文） 记录登录、Key、额度、充值、成员变更 P1

备用域名与网络 国内网络环境下，单一域名风险大 AIHubMix 在 Quick Start 给出备用域名 主域名 + 备用域名 + 状态页里写明切换方法 P0
