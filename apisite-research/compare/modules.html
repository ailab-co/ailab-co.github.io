逐模块详解

注册登录

AIHubMix

GitHub / Google / 邮箱；未登录时目标页虚化，上面盖一张登录卡；注册卡下方有企业入口。我方域名邮箱被拒，没有说明原因

kie.ai

只有 Google / Microsoft / 手机号，不能用邮箱注册；注册后直接进入 Billing 页

OpenRouter

本次未读登录页；OAuth PKCE 让第三方应用代用户授权并获得 Key [OR22]

更优
AIHubMix
我们取法

保留「虚化目标页 + 登录卡」；国内补手机号、微信、邮箱；被风控拦截时说明原因并给出申诉入口

AIHubMix 的「虚化目标页 + 登录卡」能让用户知道登录后会回到哪里，企业入口在注册环节就出现。两站的问题都在门槛：AIHubMix 拒绝我方域名邮箱却不说原因；kie.ai 不支持邮箱注册。国内客户至少需要手机号 + 微信或邮箱两种方式。

首页落地

AIHubMix

一句话定位 + 三个卖点 + 渠道、排行、生态等证据；730+ 与模型广场的 954 不一致

kie.ai

Hero + 三条承诺（失败不扣费、积分永不过期、$0 月费）+ 官方价对比表 + 精选模型 + 16 条 FAQ

OpenRouter

企业页按研发、财务、安全、采购四类角色分别讲卖点 [OR2]

更优
kie.ai
我们取法

首屏写定位和三条承诺，接着放 6～10 个热门模型的「我们价 vs 官方价」，再放 FAQ；不放点不开的状态标签

kie.ai 首页的「官方价对比表」直接回答「为什么用你」，FAQ 把失败计费、积分过期、发票、限流讲在前面；AIHubMix 首页更像品牌页。中转站以价格竞争为主，首页照 kie.ai 的结构，但数字要来自同一数据源。

模型广场

AIHubMix

左侧多维筛选，卡片显示输入/输出价、上下文、TTFT、吞吐和折扣胶囊；筛选区占掉不少首屏高度

kie.ai

厂商 + 用途两组标签，筛选写进 URL（/market/lip-sync）；卡片是深色封面，但不显示价格

OpenRouter

按模态分页签，左侧筛选；每行给出单价、上下文和累计 tokens 用量 [OR9]

更优
AIHubMix（卡片）+ kie.ai（URL 筛选）
我们取法

卡片信息照 AIHubMix；筛选做成可分享的 URL；筛选区默认收起

AIHubMix 卡片信息最全（价格、上下文、速度、折扣），适合做对比；kie.ai 的用途标签（如 Lip Sync）对多媒体用户更直观，筛选结果有独立 URL，利于 SEO 和分享；OpenRouter 用列表行展示，信息密度最高。

模型详情

AIHubMix

锚点导航：Pricing → Specs → Providers（同模型多渠道并排）→ Performance → Usage → Try → FAQ

kie.ai

页签：Playground / Examples / Similar / README / API，表单与 JSON 可切换，一页内可以试跑

OpenRouter

Providers 表并排列出各渠道价格、延迟、吞吐、Uptime，可切 P50～P99；还展示「客户实际支付均价」[OR8]

更优
文本看 OpenRouter / AIHubMix，多媒体看 kie.ai
我们取法

文本模型：价格 + 渠道表 + 代码；多媒体模型：参数表单 + 价格网格 + 试跑

文本模型的关键问题是「多少钱、走哪个渠道、稳不稳」，AIHubMix 和 OpenRouter 的渠道表正好回答；多媒体的关键问题是「参数怎么填、一条多少钱」，kie.ai 的表单 + 价格网格 + 试跑更合适。两种模板都要。

价格页

AIHubMix

没有独立价格总表，价格分散在卡片和详情页；图像按「质量 × 尺寸」矩阵，视频按秒

kie.ai

/pricing 每行给积分、我们价、官方价（或 Fal 价）、折扣；按模型分组；页签计数按价格行算（654）

OpenRouter

套餐页说明推理按渠道标价、充值时收平台费；同一模型按渠道分别标价 [OR1] [OR7]

更优
kie.ai
我们取法

照 kie.ai 做，人民币直标；计数按模型算；对比依据（官方价或渠道价）写在表头

kie.ai 价格表是本次看到的最适合转售站的形式。要改的地方：按模型计数、人民币直标、长段价格说明改成表格。AIHubMix 的「质量 × 尺寸」矩阵适合图像模型。

充值计费

AIHubMix

$15 / $50 / $100 + 自定义；手续费写明由平台承担；兑换码、USDC、自动充值（每次最少 $25）

kie.ai

4 档套餐，大额档 SAVE 5% / 10%（换算核对一致）；自动充值最多每 10 分钟扣一次；积分永不过期

OpenRouter

Standard 收 5.5%、Business 收 8% 平台费；24 小时内可在页面上自助退未用额度；支持银行卡、支付宝、USDC [OR1] [OR3]

更优
AIHubMix + kie.ai
我们取法

预设金额 + 赠送角标 + 手续费说明 + 兑换码；弹窗底部显示当前充值账户；退款规则写清楚

AIHubMix 的弹窗写明手续费由平台承担、底部显示当前账户，能防止充错号；kie.ai 把限流规则写在充值页，套餐角标和实际赠送比例一致。OpenRouter 允许 24 小时内在页面上自助退款 [OR3]，规则清楚，可以参考。

API Key

AIHubMix

创建抽屉：工作区、额度、过期、模型、IP、结构化输出修复、模型映射（≤5）、失败回退（≤3）

kie.ai

创建弹窗：有效期 1/7/30/90 天/永久；IP 默认推荐白名单，可填「最近调用的 IP / 检测我的服务器」；列表有 Safe-Spend 列

OpenRouter

Key 安全页按风险标出无限额、无过期的 Key，可批量设限、停用；Key 花费到 80% / 100% 时提醒；有管理 Key 和轮换指南 [OR24] [OR33] [OR55]

更优
kie.ai（表单）+ AIHubMix（字段）+ OpenRouter（风险视图）
我们取法

P0 做表单和安全默认值；P1 做风险列表；P2 做映射和回退

kie.ai 的安全默认值（推荐 IP 白名单、未设限的 Key 加警示图标）最值得照抄；AIHubMix 的抽屉说明了 Key 可以承载哪些策略；OpenRouter 的 Key 安全页把风险集中到一处，并能批量处理 [OR24]。

请求 / 任务日志

AIHubMix

列：时间、模型、渠道、App、输入、输出、费用、Finish reason；可设置列；Key 页可导出

kie.ai

按 Task ID、状态、日期筛选；单条或批量重发回调；保留期写在页面顶部（媒体 14 天、日志 2 个月）

OpenRouter

生成详情：渠道、费用、tokens、Finish reason、延迟、数据区域、回退过程；逐次上游尝试的瀑布图；费用拆分 [OR31]

更优
OpenRouter（深度）；AIHubMix + kie.ai（首发范围）
我们取法

P0：AIHubMix 的列 + kie.ai 的 Task ID 和保留期 + trace id；P2：回退过程和上游尝试明细

中转站的扣费纠纷要靠日志解决。首发要有：每条扣费、渠道分组、Finish reason、trace id、Task ID 搜索、CSV 导出。OpenRouter 的生成详情还会列出每次上游尝试和费用拆分（缓存读折扣、联网搜索等）[OR31]，可作为 P2 目标。

用量分析

AIHubMix

KPI（花费、请求数、tokens、缓存命中率、混合单价）+ 7 张图；可选时区

kie.ai

日期范围、导出；按接口、按 Key 两个表

OpenRouter

Overview / Trends / Explore（自定义分组）/ Guardrails 四个页签，筛选写进 URL；导出 CSV / PDF [OR30] [OR50]

更优
AIHubMix（首发）/ OpenRouter（远期）
我们取法

通知

AIHubMix

低余额（默认 $1）、新模型、下线、调价、产品更新、安全告警；可推送到 Inbox、邮件、Webhook

kie.ai

邮件订阅开关；VIP 频道宣传低余额提醒

OpenRouter

低余额（默认 $100）、模型下线、降价日报（列出新旧价格）、Key 限额 80% / 100%，可推送到邮件、Slack、自定义 Webhook [OR33]

更优
AIHubMix + OpenRouter
我们取法

P0 低余额；P1 下线 / 调价 / Key 限额 + 飞书、企微、钉钉 Webhook

AIHubMix 的规则 + 抽屉 + 目的地结构清楚；OpenRouter 的两个细节值得照抄：余额要明显回升到阈值以上才会再次提醒，避免在阈值附近反复刷屏；降价只对最近用过的模型发日报 [OR33]。

状态页

AIHubMix

status.aihubmix.com 按协议拆 5 个组件，90 天可用率（Gemini 兼容接口 92.91% 也照样公开）

kie.ai

没有找到公开状态页；首页「平台实时状态」只是一个文字标签

OpenRouter

status.openrouter.ai 按 API 端点拆组件，90 天条形图，可订阅；模型页另有按渠道的 Uptime [OR12] [OR8]

更优
AIHubMix + OpenRouter
我们取法

P1 照 AIHubMix 拆组件；P2 在模型页加按渠道的可用率

两家状态页都按协议或端点拆组件，并保留 90 天历史。AIHubMix 公开了不好看的 92.91%，反而显得可信。kie.ai 没有状态页，是 B2B 客户评估时的扣分项。

模型上新 / 下线

AIHubMix

kie.ai

控制台 API Updates 与公开 Changelog 共用一份数据，每条带文档和试用链接

OpenRouter

更优
AIHubMix
我们取法

公告中心 = 上新 + 调价 + 下线日历；下线模型返回明确的错误码

模型变动是中转站客服压力的主要来源。AIHubMix 的下线日历（公告日、下线日、替代模型）加上明确的错误码，基本能消除「这个模型怎么突然不能用了」类咨询。

工单客服

AIHubMix

kie.ai

OpenRouter

更优

我们取法

我们取法

P0：政策与实际一致；P1：数据不留存承诺 + 可选私有日志（写明保留期）

AIHubMix 的 Payment Notice 承诺停服时退还剩余余额（扣除相关费用），对预充值模式很重要；kie.ai 的隐私政策与实际做法不符，是反例。OpenRouter 默认不存提示词和输出，私有日志需要主动开启 [OR41]；开启后至少保留 3 个月 [OR32]。
