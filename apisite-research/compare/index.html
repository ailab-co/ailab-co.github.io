一句话结论

AIHubMix 擅长「治理」，kie.ai 擅长「卖货」，OpenRouter 擅长「路由与可信」。 你的站最合适的组合是：用 kie.ai 的方式标价和卖多媒体，用 AIHubMix 的方式管理 Key、日志、通知和客服，用 OpenRouter 的方式做计费规则、错误码、渠道透明和预算控制，再补上三站都没有的国内 B2B 能力（企业认证、对公充值、增值税发票、子账号与代理商）。

三站都犯过同一个错：同一个指标在不同页面给出不同数字。AIHubMix 的模型数有 730+ / 954 / 961 / 500+ 四种说法，kie.ai 有 124 / 138 / 200+ / 654 行，OpenRouter 的文档写 400+ [OR5]、价格页写 600+ [OR1]，Models API 默认返回 469 个文本模型、全部模态 718 个 [OR6]。你的站从第一天起就应该让所有对外数字来自同一个数据源，并写清口径（按模型、按价格行还是按渠道计数）。

最重要的 8 条结论

  1. 价格页是中转站的第一转化页，抄 kie.ai。 每行给出「我们价 + 官方价 + 折扣 %」，多媒体按「分辨率 × 时长 × 是否带参考输入」逐行列价，并写出计费公式。AIHubMix 的「输入/输出 + 上下文 + 限时折扣胶囊」适合文本模型卡片，两者合并。OpenRouter 的做法是写明「推理价不加价，充值时收 5.5%（Standard）/ 8%（Business）平台费」[OR1]。你做批发转售，不必照搬零加价，但应该同样把「你的钱怎么算」一句话讲清楚。
  2. API Key 是策略对象，表单抄 kie.ai，字段抄 AIHubMix，风险视图抄 OpenRouter。 kie.ai 默认推荐 IP 白名单、能一键填入「最近调用过的 IP」；AIHubMix 把额度、过期、模型范围、IP、模型映射、失败回退放进同一个抽屉；OpenRouter 有专门的 Key 安全页，用 Risk 列标出「无限额 / 无过期」，额度 ≥ $1,000 或过期超过 365 天的 Key 也会被标出 [OR24]。
  3. 计费规则要写进产品，不能只写在群公告里。 kie.ai 把限流写在充值页、保留期写在日志页顶部；OpenRouter 写明空回复和报错不计费 [OR43]，回退时只按最终成功的模型计费 [OR14]，并对并发请求做「在途预扣」，避免同时跑的请求把余额扣成负数 [OR56]。中转站最常见的纠纷正是「为什么扣这么多」和「余额怎么成负的」。
  4. 可信度靠公开数据，不靠首页的 99.9%。 AIHubMix 的状态页按协议拆组件，敢公开 92.91% 的低可用率；kie.ai 的「平台实时状态」点不进去。OpenRouter 不仅有按 API 端点拆分的 90 天状态页 [OR12]，还在每个模型页按渠道公开延迟、吞吐和 Uptime [OR8]，路由本身也依据这些实时数据 [OR59]。你的 P1 应该至少做到 AIHubMix 的水平，P2 再做到按模型、按渠道公开。
  5. 错误码必须用标准 HTTP 状态码。 kie.ai 的 /api/v1/* 出错也返回 HTTP 200，客户端无法按状态码重试和熔断；OpenRouter 区分 400/401/402/403/408/429/502/503，并带 Retry-After 头 [OR57]；AIHubMix 的错误带 tid，工单里可以填 Trace ID。你的站：标准状态码 + 中文原因 + trace id + 工单一键带入。
  6. 两站都缺「路由与容灾」这一层，这是 OpenRouter 和普通中转站的主要差距。 OpenRouter 支持同一模型按价格、吞吐或延迟给渠道排序，可以指定、排除或只用某些渠道，按价格上限、数据政策过滤 [OR13]；也支持模型级回退数组 [OR14]，用 :floor（最便宜）/:nitro（最快）后缀切换偏好 [OR18] [OR17]，用 ~latest 别名自动跟随新版本 [OR20]。你的后端（new-api 类，推断）已有渠道权重和重试，主要工作是把它变成用户能选、能看到结果的产品功能，并在日志里显示每次实际走了哪个渠道、是否发生了回退。
  7. 企业与团队能力，OpenRouter 的分层最清楚，但个人用户为主的站不必首发就做。 OpenRouter 的结构是：组织统一出钱，工作区隔离 Key、路由默认值和观测配置 [OR37]，工作区预算按日、周、月或累计封顶 [OR38]，护栏按成员或 Key 限额、限定可用模型 [OR36]，再往上是 SSO/SCIM [OR47]。对你的 B2B 客户，最先需要的是「一个企业账号 + 多个子账号/项目 + 各自额度 + 统一开票」，SSO 放到 P2。
  8. 国内 B2B 的硬需求三站都没有：实名/企业认证、对公转账、增值税发票、合同和对账单。 AIHubMix 的发票要走工单；kie.ai 的发票在 Billing 页手动生成；OpenRouter 支持在发票上加税号，通过 Stripe 计税 [OR51]。这些都不适用于国内对公。国内可参考硅基流动：实名后才能充值和开票，企业认证可开增值税专用发票，只对已消费金额开票 [X5] [X7]。这是你相对三站最容易建立的差异化。

给光哥的建议方向

定位

「面向国内开发者和中小企业的透明 AI 模型网关：一个 Key 调文本和多媒体，人民币结算，可开发票，价格、渠道、可用率都摆在明面上。」

五个核心差异化（按重要度）

  1. 价格透明：每个模型都给「我们价 / 官方价 / 折扣」，人民币直接标价（不搞积分换算）；多媒体写计费公式；同一模型不同渠道或分组的价格并排列出，渠道来源写清楚。
  2. 计费可核对：报错和空回复不扣费，回退时只按实际成功的那次计费，并发请求先预扣，日志里每条都能看到扣费明细和 trace id。规则写在价格页、充值页和日志页，而不是只写在群公告里。
  3. 国内 B2B 闭环：企业认证 → 对公转账 → 增值税发票（按已消费金额开）→ 合同与月度对账单 → 子账号/项目额度。这一块三站都没有。
  4. 可信度公开：状态页按协议和模型族拆组件；公告中心集中发布上新、调价和下线（带替代模型）；通知推送到飞书、企业微信或钉钉。
  5. 多媒体与文本一体：文本走 OpenAI / Claude / Gemini 兼容协议直连；图像、视频、音乐统一走「创建任务 + 查询 + 签名回调」，保留期写在日志页。

明确不做（至少首发不做）

  • 不做积分制和「看起来像真实数据」的营销数字；不在首页放点不开的「实时状态」。
  • 首发不做 SSO/SCIM、私有化部署、Auto Router 和 MCP。这些是 OpenRouter 和 AIHubMix 的企业级功能，个人和小团队客户用不上，先把 P0 做扎实。
  • 不照搬 kie.ai「错误也返回 200」和「回调签名不覆盖请求体」，也不照搬 AIHubMix「GET 请求会轮换 Key」。

分阶段路线（P0 / P1 / P2）

P0 首发（约 4～6 周的用户端重做范围，按 new-api 类后端已有能力估算，属推断）

  • 价格页 + 模型广场：我们价 / 官方价 / 折扣列，人民币标价；按模态、厂商、用途筛选，筛选状态写进 URL；多媒体按分辨率逐行列价并写计费公式。
  • 模型详情页 v1：价格表（输入、输出、缓存读、缓存写）、上下文、能力清单、可复制的代码示例（Base URL 和模型名已填好）。
  • 控制台首页：余额、本月花费、「创建 Key → 复制代码」两步完成首次调用。
  • Key 创建抽屉：名称、额度、有效期、模型白名单、IP 白名单（默认推荐，可一键填入最近调用的 IP）；列表用警示图标标出「任意 IP / 永不过期 / 无限额」的 Key。
  • 请求日志 + 任务日志：时间、模型、渠道分组、输入/输出 tokens、扣费、状态、Finish reason、trace id；任务按 Task ID 搜索；支持 CSV 导出；保留期写在页面顶部。
  • 充值页：人民币预设金额 + 赠送比例角标 + 支付方式 + 兑换码 + 交易记录；限流规则写在同一页。
  • 计费规则：标准 HTTP 错误码；报错和空回复不扣费；并发请求预扣。
  • 实名 / 企业认证 + 发票申请：先上线表单和人工处理流程，再逐步自动化。
  • 低余额告警（邮件 + 站内信）；错误码 FAQ + 工单（带 trace id）；接入必读一页；主体、条款、隐私、退款、发票政策。

P1 第二阶段（上线后 1～3 个月）

  • 公开状态页（按协议 / 模型族拆组件）；公告中心（上新 / 调价 / 下线日历 + 替代模型）；通知推送到飞书、企业微信、钉钉的 Webhook。
  • 项目（工作区）层：把令牌分组包装成项目，每个项目单独看花费、Key 和日志，并设日、周、月预算。
  • 用量分析：按 Key / 模型 / 成员统计，展示缓存命中率和混合单价；时区默认 Asia/Shanghai。
  • 子账号与团队：成员、角色、额度分配；企业统一付款、统一开票。
  • 网页 Playground（文本 + 图像），余额不足时直接引导充值；在常用工具里接入的教程卡片（Cherry Studio、Cursor、Claude Code、Dify）。
  • 推广返佣（申请制、安全期、防刷、周结算）；付费客户专属飞书或企业微信群。
  • 响应内返回 usage 和 cost；余额与 Key 查询接口；llms.txt；Changelog + RSS。

P2 远期（有数据、有企业客户之后）

  • 路由偏好：渠道优先级、「经济 / 高速」两种模式、模型级回退数组、latest 别名；每个模型按渠道公开 Uptime、延迟和吞吐。
  • 预设（模型 + 参数 + 系统提示词）、批量接口（Batch）、相同请求缓存。
  • 代理商 / 分销：下级账号、加价规则、对账单（服务你的 B2B 转售客户）。
  • 管理 API（先做只读）、MCP / CLI；模型对比页；本站用量排行。
  • 企业：审计日志、SSO、数据不留存承诺、SLA 与赔付条款。
